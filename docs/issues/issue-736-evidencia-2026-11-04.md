# Issue 736: TPK40 DTS/TrueHD feasibility — 2026-11-04

The current TPK40 build excludes FFmpeg and its runtime conversion path requires Tizen 6+ (or unknown). The requested Tizen 4/5 capability remains unimplemented and unvalidated on a TV.

At integration base `8ceba0407f63cdaafe10a96e571592189639cfb5`, an isolated experiment linked an FFmpeg-enabled ARM TPK40 library using cached dependencies in `/Volumes/ExternalSSD/nv-736-tpk40`. Build exited 0. `tests/tpk40_tls.sh` passed: no PT_TLS, ARM TLS relocations or `__tls_get_addr`; DT_HASH present. ELF inspection found `R_ARM_RELATIVE`, `R_ARM_JUMP_SLOT` and `R_ARM_GLOB_DAT`, supported by the fallback loader, and matching `nv_tpk*` exports. The experimental library is 32,972,988 bytes with 322,279 relative relocations. Logs: `build/experiment/build.log` and `build/experiment/elf.log` in that worktree. The experiment bypassed TLS rejection only in a generated diagnostic script and inspected the resulting library; production script was not changed. The container CLI displayed local image/kernel startup messages labeled Fetching; networking was not disabled, though no download command was invoked.

Static inspection does not prove loader execution, runtime dependency availability, ABI compatibility, acceptable startup or memory, UEP, conversion or playback. No TPK containing this binary was built. Current TPK40 packaging explicitly excludes and rejects FFmpeg notices, so packaging requires an appropriate change with its licenses before a viable package exists. A subsequent experiment packaged the previously built ELF into a 47 MB TPK under macOS sandbox network denial, with local NuGet packages and isolated HOME/cache. A socket connection under the same sandbox failed with EPERM. Archive integrity passed; artwork, the ELF and both cached FFmpeg license/provenance notices were present, and their bytes matched the originals. Package SHA256 `814cec2e634820de887e26530efa5be4608db1dee593cf4db93192cab9d8b2df`; script and log: `build/experiment/package-offline.sh` and `package-offline.log` in the experimental worktree. The earlier native compilation ran in an Apple container without enforced network isolation, so a full source-to-package offline build is not proven. The regular production script still excludes FFmpeg and its notices from TPK40. No production changes were made. First-run dotnet reported installing an ASP.NET Core development certificate; host keychain impact was not verified. Next: validate the loader and conversion in a suitable Tizen 4/5 environment, and measure actual playback and resources; do not assume package creation establishes support.
